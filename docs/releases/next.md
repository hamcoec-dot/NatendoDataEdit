## Not yet released

- **Show me the rule (fill by example):** Data › Show me the rule (Ctrl+Shift+E) shows the rule fill by example learned, as a form you can change, with a preview of the first cells it fills, the count and the odd-looking results. When one example disagrees with the others it is named, with Leave it out and Go to row. Apply fills with that exact rule (recipes keep it); Save as formula makes a computed column. After Ctrl+E the status line now says how many results look odd, with Show the rule.
- **Save JSON back to its file:** a JSON Lines or JSON file of records opened from Import now saves back to that file with Ctrl+S, in its own format: numbers exactly as written, `true`/`false`, `null`, missing keys and nested values as they were, and the file's line endings and indent. The first save with a newly blank cell asks whether to leave the key out (the default), write `""` or `null`, once per file. Save As offers JSON Lines and JSON. A record with the same key twice can only be saved as another file, and Save says why.
- **Fixed: JSON import rounded nested numbers.** A big ID or `1.50` inside a nested object or array came in as `1.5` or rounded; it is now kept exactly as the file writes it.

- **Processing receipts:** tick "Write a processing receipt" in Save As, Run a recipe on files or Watch a folder (or `--receipt` on `natendo-cli run` and `convert`) for a sealed `name.ndreceipt.json` beside each file written: file names, sizes and SHA-256 hashes in and out, times, version and step kinds, no cell values. Tools > Verify a processing receipt and `natendo-cli receipt verify` check it, the files and the chain. Tamper-evidence, not a signature.
- **Behaviour change: with rows hidden, sorting and new computed columns act on the shown rows.** Sort, the quick sorts and "Put failing rows first" leave hidden rows where they are, and a new computed column leaves them empty, unless you tick the box that includes them. Recipes saved by earlier versions still act on every row. Tools that change hidden rows anyway now say how many.
- **Fixed: Changes from a newer file with hidden rows.** With rows filtered or hidden, it could offer to add a second copy of a hidden row, or to delete a row the newer file still had. Every row of both tables is now compared; changes to hidden rows are marked, and a hidden row is never deleted without being ticked. Tools that read another tab say how many of its rows are hidden. The review list now shows each old and new value (they were squeezed out of sight).
- **CSV export safety** (on to start with): in the list of changes, the report of what changed since a checkpoint and the share-safe copy, a cell that a spreadsheet could run as a formula gets one apostrophe in front, so it shows as text. Split into files has its own tick, off to start with. Saving your own file never changes it.
- **Shifted rows:** a note on opening counts the rows with a different number of fields than most, and the Data menu shows only those, the short ones or the long ones.
- Emptying a cell past the end of a short row no longer adds empty fields to it.
- **Leading zeros from LibreOffice sheets:** a number an `.ods` sheet shows as `00123` can now be imported that way, with the same question as for Excel files. Excel formats written with quoted dashes or spaces (`00"-"000`) are recognised too.
- **Repair bar:** fix a shifted row where it broke: join fields, join it with the next or previous row of the file, or read a stray quote mark as text, with a preview and one undo step. **Fix all like this** repairs every row of the same shape at once, and the emptied extra column can be removed.
- **Find gaps in a sequence:** Data > Find gaps in a sequence lists the numbers or IDs missing from a column as ranges, with repeats and out-of-order rows, and can show the rows next to each gap. Dates too: by day, business day, week, month or every so many days. Also `natendo-cli gaps`.
- **Ambiguous dates:** Check dates in this column lights the dates that could be read two ways and says what the column tells about their order.
- **Clean matrix:** Clean > Clean matrix cleans many columns at once, each with its own ticked steps, with exact preview counts, in one pass, one undo step and one recipe step.
- **Compare lists:** Data > Compare lists counts the keys shared by 2 to 5 open tabs, slice by slice, and opens any slice as a tab. Also `natendo-cli sets`.
- **Combine by title no longer loses data.** When a file had two columns with the same title, the second overwrote the first. Both are now kept, as `Note` and `Note (2)`. A file that already has a `Source file` column keeps it when you add the file-name column, which is then numbered.
- **`natendo-cli cat --by-name` keeps every column.** It had the same loss, and also silently left out columns the first file did not have. The output now has every file's columns.
- **`natendo-cli --json` works on every command.** It was ignored by `headers`, `select`, `filter`, `sort`, `dedupe`, `stats`, `count`, `sample`, `slice`, `split`, `cat`, `clean`, `convert`, `compute`, `run` and `pivot`. Scripts that already passed it will now get JSON.
- **Shapefile attribute tables:** open a `.dbf` (or the `.shp` beside it), with the text encoding picked for you and shown, and a FID column to join your edits back to the shapes. The `.dbf` is never written.
- **GeoPackage:** open a `.gpkg` and pick a layer or attribute table. Shapes are left out; nothing is written beside the file. `.gpkg`, `.sqlite` and `.sqlite3` files now open from Open, drag and drop and double-click.
- A SQLite database in write-ahead mode with unsaved changes in its `-wal` file (or an unfinished `-journal`) is no longer opened, because reading it could create or change files beside it. Close it in the program using it first.
- **Recipes with a dates step:** a step recorded from now on says what it does with ambiguous dates (left as typed, month first or day first). Older recipes keep their behaviour.
- **Find relationships:** Data > Find relationships shows which columns settle which, which are one to one or blank together, and the rows that break each.
- **Totals row:** View > Totals row pins one total per column under the table, over the rows shown. Columns of IDs and codes are counted, not added.
- **Outside changes:** a banner says when another program changes or deletes an open file, with Reload, Compare with disk and Ignore.
- **No repeats across several columns:** a data check can say that two or more columns together may not repeat (first + last name + date of birth), with every key cell of a repeated row marked. Data > No repeats across these columns together makes one from the selected columns; `natendo-cli validate` reads it with `"also_columns"`.
- **Values that must exist in another file:** a data check can say a value must be one of a column's values in another open file (or the same file), with case, spaces and blanks choices. A rule whose file is not open does not run and says so; Show only rows with problems and the other problem tools wait for it. `natendo-cli validate --table name=file` gives the files.
- **Table checks:** rules about the whole table, run with the data checks: the number of rows (or as many as another open file), no blanks in a column, how many different values, and totals that must add up, like `SUM([Early]) + SUM([Election day]) = SUM([Total])`, equal within an amount or a percent. Each says passed or failed with the figures. Data > Table checks; `natendo-cli validate` reads `"table_checks"` too.
- **Report notes:** a report's title lines and its total line can be set aside from the table and are saved back where they were. Right-click the column-titles row › Headers start here, or select the last rows › Set aside rows as footer notes; View › Report notes shows them, keeps them in saves (a switch) and puts them back. Rows you did not edit keep their exact bytes. A total line at the end is spotted when a file opens: a bar says whether the rows above add up to it and offers to set it aside, delete it (only when it adds up) or keep it.
- **Fill down by group:** Tools › Fill blank cells can stop the fill at rows where a chosen column (an ID, say) is blank, at blank rows and at total rows (Total, Subtotal, Grand total or Sum with a number), so a label no longer bleeds into spacer and subtotal rows or the next group. The dialog counts what it will fill and leave blank before Run; the cells left blank are then marked amber (F7 visits them, Esc or Ctrl+Z takes the marks away). All the stops are off unless you turn them on.
- **Merge values by dragging, with dictionaries:** in Data › Edit values, drag one value onto another (or tick several and press Ctrl+M) to merge them; Undo merge steps back before anything changes. A new Look-alikes choice groups abbreviations and full names (St = Street, NY = New York, USA = United States); state codes in a column that is mostly not states are only offered one at a time. Merges can be saved as a dictionary and loaded next time, with the values new since then listed to drag into place.
- **Explode cells:** Data › Explode cells turns a column of JSON objects, JSON lists, `a=1;b=2` pairs or `vip|beta` lists into one column per key, one row per item, one column per position or one flag column per item. It says what the column looks like, shows the first 20 rows before and after, counts the cells that do not parse (they stay as they are; Show those rows filters to them) and keeps numbers exactly as written. One undo step; a recipe keeps the chosen keys and names any new key in its run report.
- **Filter chips:** while a filter is on, a bar above the grid shows each column rule and each tool that showed rows (duplicates, problems, a formula and the rest) as a chip. Click to switch one off, × to take it out, right-click to invert, edit, rename, show a formula's error rows or run the tool again. Match all or Match any, and Invert all. A tool's rows now join the filter beside the other chips instead of replacing it. Each change is one undo step; View › Filter chips hides the bar.
- **Hidden rows are marked:** a dotted line in the row numbers shows where rows are missing, and the status bar says which rows edits act on.
- **More of the app on the command line:** `natendo-cli compare` (two versions of a table by key, with a differences file), `match` (rows that look like the same person), `lookalikes`, `xray` (and `xray --sanitize`), `encoding detect` and `encoding scan`, `private`, `share-safe`, `encrypt` and `decrypt`, plus `--encoding` for reading and `convert --to-encoding` for writing. They give the same results as the app. Phrases and passwords come from standard input, a file or an environment variable, never the command line; a share-safe spec goes by column titles and refuses a file it does not fit; a failed command leaves no output file.
- **Behaviour change: `natendo-cli patch` also reads its phrase from `NATENDO_PHRASE`**, and `clean` and `run` refuse a cleaner or recipe file that holds a phrase or password (`--allow-phrase-in-file` reads it anyway).
- **Combine with a column map:** Combine files by title now shows how the columns line up before combining, lets you change it, suggests columns that are probably one under two titles (with sample values; never applied by itself), and saves the map (titles only) for next month. Each file is checked again before combining. `natendo-cli cat --mapping map.ndcombine [--strict]` uses a saved map, and `cat --plan` shows the line-up without writing.
- **Relationships become checks:** in Data › Find relationships, Make this a check adds a data check that marks the rows breaking a line ("Ward the same for each Precinct"; both ways for one to one; a row rule for blank together), counted the way the scan counts it. The rule is also in Data checks as "Same for each value of another column". Rules files that hold it are saved as version 3, which older versions of the app cannot open (other rules files open in them as before).

**Fixed: moving across the grid with the keyboard could leave the first column cut in half.** Arrow keys, Page Up and Down, Ctrl+End, Go to and Find now scroll by whole columns and rows, as spreadsheets do. A click on a part-shown cell still moves the view only a little, so the cell stays under the pointer, and the mouse wheel and scrollbars still scroll smoothly.

**Fixed: `natendo-cli` crashed when its output was cut short.** Piping a command into `head` (or anything that stops reading) made it stop with a "failed printing to stdout" panic and exit code 101. It now stops printing quietly, finishes any file it writes, and exits with the command's own result.

**Fixed (data safety): blank templates read with the wrong separator.** Blank templates (titles over empty rows) now open with the right separator; before, typing into one could save the wrong columns. Files whose middle columns are blank on every row (an ID and a ward, names left empty) also keep their comma.
